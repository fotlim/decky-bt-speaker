## 提交流程

```bash
# 1) fork 数据库仓库
gh repo fork SteamDeckHomebrew/decky-plugin-database --clone
cd decky-plugin-database

# 2) 加 submodule
git submodule add https://github.com/fotlim/decky-bt-speaker plugins/decky-bt-speaker

# 3) 开分支提交
git checkout -b add-decky-bt-speaker
git add .gitmodules plugins/decky-bt-speaker
git commit -m "Add decky-bt-speaker plugin"
git push -u origin add-decky-bt-speaker

# 4) 开 PR
gh pr create --repo SteamDeckHomebrew/decky-plugin-database \
  --title "Add decky-bt-speaker" --body-file /tmp/pr-body.md
```

## 差异化说明（审核可能问）

### Q: SteamOS 3.7 起本来就能当蓝牙音箱，为什么还需要这个插件？

A: 系统确实能，但有四个实际痛点没有解决：

1. **180 秒后自动隐身** —— BlueZ 的 `DiscoverableTimeout` 默认 180 秒，之后手机就搜不到了。插件设为 0 并每分钟保活。
2. **容易掉成通话单声道** —— HFP/HSP 会抢 A2DP，声音变闷。插件关闭 `autoswitch-to-headset-profile`。
3. **双角色设备连上没声音** —— 上游回归（wireplumber#969 / bluez#1922），设备被协商成 `audio-gateway`。插件收窄 `bluez5.roles` 规避。
4. **接收端拿不到蓝牙硬件音量** —— `bluez5.hw-volume` 默认值不含 `a2dp_sink`。插件显式补上。

另外插件还提供了系统完全没有的东西：跨睡眠保活、外部音源独立音量、AVRCP 元数据显示、EQ、多输出同步。

### Q: 会不会和现有插件冲突？

A: 不会，是互补关系。已做全量调研（118 个商店插件）：

| 插件 | 做什么 | 与本插件的关系 |
|---|---|---|
| Outpox/Bluetooth | Deck 连出去（耳机） | 互补：方向相反 |
| MagicPods | 耳机侧智能（ANC/电量） | 互补 |
| Volume Mixer | 每应用音量 | 互补 |
| DeckSP / DeckyEQ | DSP 处理 | 互补（本插件的 EQ 是轻量内置方案） |

**「Deck 接收外部音频」这块在 118 个插件里是空白的**（GitHub 搜 `decky a2dp` / `decky bluetooth sink` 均为 0 结果）。

### Q: 为什么要改 PipeWire / WirePlumber 配置？

A: 全部写在**用户目录**，不碰只读根分区，不需要 root：

| 文件 | 作用 |
|---|---|
| `~/.config/wireplumber/wireplumber.conf.d/50-bt-speaker.conf` | 音箱优化 |
| `~/.config/wireplumber/wireplumber.conf.d/70-bt-speaker-latency.conf` | 延迟档位 |
| `~/.config/pipewire/pipewire.conf.d/60-bt-speaker-eq.conf` | 均衡器 |
| `~/.config/pipewire/pipewire.conf.d/70-bt-speaker-combine.conf` | 多输出 |

**每项都是可选的、默认关闭的**，且都能在 UI 里一键移除。不写 `/etc`，不受 SteamOS 升级的保留清单影响。

### Q: 会不会影响用户的默认音频设备？

A: 不会。**刻意不使用 `wpctl set-default`** —— 那个选择会被永久记住，且在 `find-selected-default-node.lua` 里获得 `priority = 30000 + priority` 加成，压过所有 `priority.session`，用户之后在系统里怎么切都会被抢回去（见 [GNOME #3800](https://gitlab.gnome.org/GNOME/gnome-control-center/-/work_items/3800)）。

插件只做一次性的路由修正，不写入持久状态。用户自己选的默认设备永远优先。
