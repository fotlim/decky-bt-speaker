# 功能拓展与竞品调研

> 给「蓝牙音箱」插件（decky-bt-speaker）做的方向性研究。
> 所有结论带出处；凡属推断均标注「待验证 / 未证实」。

---

## 一、竞品调研：这个位置是空的

### 1.1 Decky 商店全量扫描

对 [Decky 商店](https://plugins.deckbrew.xyz/plugins) 118 个插件做交叉筛选（audio / bluetooth / sound / sink / receiver / route），结果：

| id | 插件 | 作者 | 做了什么 | 与我们的关系 |
|---|---|---|---|---|
| 18 | **Bluetooth** | Outpox | 快速连接已配对设备（jeepney 直连 bluez D-Bus） | 互补：它管「往外连」 |
| 38 | **Volume Mixer** | Isiah Lloyd | 每应用音量 + 蓝牙设备媒体键 | 互补：它读 `sink_input_list()`（播放流） |
| 144 | **Mixer** | Kirill Nikiforov | PipeWire 版每应用音量（`pw-dump` + `wpctl`） | 互补 |
| 82 | **MagicPods** | Maslov & Litvintsev | AirPods 电量/ANC/EQ/编码器切换 | 互补：它只管「耳机侧」 |
| 100 | **Virtual Surround Sound** | Josh.5 | filter-chain 建虚拟 7.1 sink | 可借鉴：filter-chain 用法 |
| 102 | **DeckSP** | Jesse Bofill | 完整 DSP（EQ/混响/压缩），后端是 JamesDSP flatpak | 可借鉴：DSP 包装范式 |
| 139 | **Output Manager** | joeatethebeans | QAM 切显示器 + 音频输出 | 互补 |
| 77 | **BT Wake Control** | FineWolf | Wake-on-Bluetooth 开关 | 互补 |
| 147 | **Pixel Buddy** | Phill Moon | Pixel Buds 电量 + ANC | 互补 |
| 16/52/24/58/12/111/142 | Audio Loader / Game Theme Music / RadiYo! / Volume Boost / MusicControl ×2 / MuteOnSleep | — | 音效替换、主题曲、电台、增益、MPRIS、唤醒静音 | 无关或互补 |

**未进商店但生态里存在的**（做竞品时会撞上）：

- **Shared Headphones** — 音频同时分给两副蓝牙耳机，各自独立音量（[GitHub](https://github.com/Tonksthebear/decky-shared-headphones)）
- **Audio Output Switcher**（zomars）— 走 `SteamClient.System.Audio` 切默认输出，零 flag 零 subprocess（[GitHub](https://github.com/zomars/audio-output-switcher)）
- **DeckyEQ**（Rayek）— 自带 `deckyeq_dsp.so` 原生 DSP，明确写「无需 root」（[GitHub](https://github.com/Rayekkk/DeckyEQ)）
- **Ally DSP**（bassobr）— filter-chain + 打包 LSP LV2，**systemd user service** 常驻（[GitHub](https://github.com/bassobr/decky-ally-dsp)）

### 1.2 结论：品类空白

三重交叉验证：

1. 118 个商店插件里，按 `a2dp|sink|receiver|speaker|route` 扫，唯一命中是 Virtual Surround Sound（HRIR 虚拟 sink，与蓝牙无关）
2. GitHub 搜索 `decky a2dp` / `decky bluetooth sink` / `decky audio receiver` → **全部 0 结果**
3. 插件库 PR 搜索 `a2dp` → 只有 MagicPods 的版本更新

**现有插件全都在做「Deck 往外送音频」和「调 Deck 自己的音频」，没有一个是「Deck 往里收音频」。**

具体空在哪：

- ❌ 没插件把 Deck 广播成可发现的 A2DP sink（`Class: 0x240414`、`Audio Sink` UUID）
- ❌ 没有配对/自动接受 agent 的 UI（现在要钻桌面模式 KDE 蓝牙设置）
- ❌ 没有「谁在放歌」的可见性（手机连上后 QAM 一片空白）
- ❌ 没有外部音源与游戏音量的混音界面
- ❌ 没有把编码器协商 / 延迟取舍暴露给用户
- ❌ 没有跨 suspend 保活
- ❌ 没有「游戏音频 + 手机音频」的 ducking / 优先级策略
- ❌ **EasyEffects 至今没有 Decky 包装**（GitHub 搜索 0 结果）

## 二、硬约束：这些事做不到，别写进路线图

做功能规划前必须先认命的部分。**能省掉大量白工。**

### 2.1 同一适配器只能有一个 A2DP 源设备 ⛔

这是**协议级**限制，不是软件没做好：

- **AVDTP v1.3 §5.3**：同一适配器上的一个本地 SEP 只能连**一个**远端 SEP
- PipeWire 作者 Wim Taymans 的提交原文：「bluez5: endpoint can be used only by one device at a time ... Trying to have it connected to multiple remotes either fails or causes misbehavior later on」（[GitLab](https://gitlab.freedesktop.org/pipewire/pipewire/-/commits/a58d8150249c31d3bb37844ec98563eddd5cf143/spa/plugins)）
- PulseAudio 时代同样结论：第二台设备一连就被踢（[邮件列表](https://lists.freedesktop.org/archives/pulseaudio-discuss/2016-July/026562.html)）

> **所以「两台手机同时连 Deck 放歌」是做不到的。** 网络上有些文章说「no real limit to the number of inputs」，指的是**多台设备可以同时保持 ACL 连接**，但同一时刻只有一条 A2DP 流能真正出声。

**可行的替代**：1 路蓝牙 A2DP + 本机 App 音频 + 网络源（AirPlay/Snapcast）混音。这是「多源」的正确做法。

### 2.2 反向（Deck → 多个蓝牙耳机）是可行的 ✅

`module-combine-stream` 的 `combine.mode = sink` 能把一个虚拟 sink 转发到多个真实 sink，含多台蓝牙设备，`combine.latency-compensate` 做延迟对齐。已有实测（[grueter.dev](https://grueter.dev/blog/pipewire-combine-sinks/)）。Shared Headphones 插件做的就是这件事。

### 2.3 AirPlay 接收端的坑

- **shairport-sync 官方承认与蓝牙配合不好**：「does not work very well with Bluetooth」（[AirPlay 2 说明](https://raw.githubusercontent.com/mikebrady/shairport-sync/master/AIRPLAY2.md)）——**AirPlay 的时序经验不可直接复用到 A2DP 插件**
- shairport-sync / UxPlay / librespot 都是**外部二进制**，Decky 商店对「未静态链接的第三方二进制」审核严格，PR 模板里要专门声明
- **librespot 有 DRM 死结**：Spotify 改了取密钥机制，某日期后新注册账号拿不到音频密钥，全版本无解（[README](https://github.com/librespot-org/librespot)）

### 2.4 SteamOS 升级会改东西

- Valve 在维护自己的 PipeWire/WirePlumber 定制（[valve-hardware-audio-processing](https://github.com/evlaV/valve-hardware-audio-processing)）
- MagicPods 就因 SteamOS 改了编码器命名而需要适配（[博客](https://magicpods.app/blog/post-15/)）
- **所以：配置一律走 `~/.config` 用户态，编解码器名字别写死，找不到就降级。**

## 三、创新方向：分三层

### 第一层：把核心做扎实（v1.1，低风险高收益）

这些是「用户真的会碰到」的问题，抄自成熟产品但没人移植到 Deck。

| # | 功能 | 抄自 | 价值 |
|---|---|---|---|
| 1 | **连接即自动接管 / 断开即回落** | Sonos `Autoplay Room` | 蓝牙一连上自动切默认 sink，断开自动回 Deck 喇叭，全程零点击 |
| 2 | **静音自动断开** | Airfoil `Silence Monitor` | 连续静音 N 秒断开 A2DP，省电、防「手机以为还连着」吞掉通知 |
| 3 | **音量归一化而非同步** | Sonos [音量规范](https://docs.sonos.com/docs/seg-volume.md) | 连上**先读**手机侧音量再对齐 UI，**绝不反向改手机音量**（否则一插上就炸音） |
| 4 | **跨 suspend 保活 + 自动重连** | 无先例 | Deck 睡眠唤醒后 A2DP sink 状态检查与恢复，这是掌机独有痛点 |
| 5 | **「谁在放歌」实时显示** | 无先例 | QAM 显示外部源设备名 + 编码器 + 码率，解决「连上了但不知道有没有在响」 |

> 第 4 条是**掌机独有**的，桌面软件不需要处理。这是最容易做出差异化的地方。

### 第二层：差异化能力（v1.2，需要一些 PipeWire 功夫）

| # | 功能 | 技术路径 | 备注 |
|---|---|---|---|
| 6 | **音频焦点策略** | 三档：接收端优先 / 与游戏共存 / 手动 | 抄 AudioRelay 的 `Audio focus` 开关。解决最高频投诉「一接蓝牙游戏就没声」 |
| 7 | **手机音量独立一档** | `wpctl set-volume <bluez_input 节点 id>` | 现在只能调总音量，手机推来的流过响时没法单独压 |
| 8 | **游戏 + 手机混音** | `module-filter-chain` 的 `mixer`（8 路输入 + 每路 Gain） | 宿舍/合租场景的核心需求（xeiaso 的原始动机就是这个） |
| 9 | **延迟档位 + 估算 ms** | `bluez5.decode-buffer.latency` / `node.latency-offset-msec` | 抄 SoundWire Pro Mode：给「省电/低延迟/抗卡顿」三档并显示当前延迟 |
| 10 | **编码器协商暴露** | `bluez5.codecs` 收窄 + 显示当前 codec | 让用户知道自己在用 SBC 还是 AAC |
| 11 | **AVRCP 元数据回传** | 读 `org.bluez.MediaPlayer1` | 在 QAM 显示曲名/封面，Deck 屏幕不再黑着 |

### 第三层：有想象空间（v2.0，需验证）

| # | 想法 | 可行性 | 说明 |
|---|---|---|---|
| 12 | **蓝牙中继器**：手机 → Deck → 蓝牙耳机 | ⚠️ 待验证 | `a2dp_sink` + `a2dp_source` 同时开 + loopback 串起来。**延迟会叠加**，但「把有线耳机变无线」这个场景很香 |
| 13 | **多输出同步**：Deck 喇叭 + 蓝牙耳机同时响 | ✅ 可行 | `module-combine-stream` sink 模式，聚会时两人听同一局游戏 |
| 14 | **EQ / 耳机补偿** | ✅ 可行 | `filter-chain` 的 `param_eq` 可直接吃 AutoEQ 配置。**EasyEffects 在 Decky 里是空白位**，谁先做谁占 |
| 15 | **响度归一化（LUFS）** | ✅ 可行 | `ebur128` + `lufs2gain`，根治「手机切歌音量忽大忽小」 |
| 16 | **网络接收端**（AirPlay / DLNA） | ⚠️ 有审核风险 | 需要外部二进制，且 shairport-sync 官方说与蓝牙配合差。**建议做成独立插件**，别混进来 |
| 17 | **免提模式**（HFP AG） | ⚠️ 音质代价大 | 开 `hfp_ag` 能让手机电话走 Deck 麦克风，但会掉成 mSBC 单声道。**与「音质优先」的定位冲突，谨慎** |
| 18 | **录制/回放** | ✅ 可行 | 把手机推来的流录成文件，或用 `pw-record` |

## 四、最值得做的三件事（本鱼的意见）

如果只能做三件，本鱼会选：

### ① 跨 suspend 保活 + 自动重连（掌机独有，零竞品）

Deck 的核心使用姿势是**随手合盖、随时唤醒**。桌面软件不需要处理这件事，所以没有任何现成方案可抄——这正是差异化所在。

**具体做法**：监听 `logind` 的 `PrepareForSleep` 信号，唤醒后检查 adapter `Powered` / `Discoverable` / 设备 `Connected` 状态，缺失就自动补。配合现有的 60s 保活循环。

### ② 「谁在放歌」+ 手机音量独立控制（体验闭环）

现在用户连上手机后，QAM 里**什么都没有**——不知道有没有连上、不知道谁在放、不知道音质如何。把这条链路补完，插件才从「开关」变成「面板」。

**具体做法**：读 `wpctl status` 找 `bluez_input.*` 节点 → 显示设备名/编码器 → 给它单独一个音量滑杆。

### ③ EQ（占住 EasyEffects 的空白位）

调研确认 **Decky 生态里没有任何 EasyEffects 包装**（GitHub 搜索 0 结果），而 Deck 自带喇叭和便宜蓝牙音箱的频响都不怎么样，EQ 是**感知提升最大**的功能。

**具体做法**：`filter-chain` + `param_eq`，预设几档（人声 / 低音 / 平直），支持导入 AutoEQ。不用装 EasyEffects，纯 `~/.config/pipewire/pipewire.conf.d/` 配置文件即可。

## 五、定位建议

**不要**把插件说成「让 Deck 能当蓝牙音箱」——SteamOS 3.7 起本来就能。

**要**说成：

> **把 Steam Deck 变成一台「好用的」蓝牙音箱与音频中枢。**

关键词是**好用**和**中枢**：

- **好用** = 发现/配对/保活/音质/延迟这些坑都填平
- **中枢** = 不只是被动接收，而是「手机 + 游戏 + 耳机」的汇合点

与现有插件的关系是**互补**而非竞争：

```
Outpox/Bluetooth  → Deck 连出去（耳机）
MagicPods         → 耳机侧的智能（ANC/电量）
Volume Mixer      → 每应用音量
decky-bt-speaker  → 外部音源流进来  ← 只有我们在这
DeckyEQ / DeckSP  → DSP 处理
```

## 六、工程注意事项（给后续开发者）

### 6.1 `_root` flag 其实不存在 ⚠️

调研实证：官方模板 `plugin.json` 写的是 `"_root"`，但 **loader 源码实际判断的是 `"root"`**：

```python
setgid(UserType.EFFECTIVE_USER if "root" in self.flags else UserType.HOST_USER)
```

核对 `v3.0.0` / `v3.2.0` / `v3.3.1` / `main` 四个版本全部是 `"root"`，全仓库 grep 不到 `_root` 处理逻辑。商店里所有真正要 root 的插件（XR Gaming、DeckMTP、WiFi Locker 等）用的都是 `"root"`。

**本插件不需要 root，`flags: []` 是对的。**

### 6.2 常驻任务别自己造轮子

已有现成模板（[Ally DSP](https://github.com/bassobr/decky-ally-dsp/blob/main/docs/architecture.md)）：

- 渲染 `~/.config/systemd/user/*.service`
- `After=pipewire.service wireplumber.service`、`BindsTo=pipewire.service`、`Restart=on-failure`、`Slice=session.slice`
- `systemctl --user daemon-reload / enable / start`
- 架构文档第一句：「It runs without root and writes only below the user's home directory.」

**不要**为了常驻加 root flag——商店审核不喜欢，`systemctl --user` 完全够用。

### 6.3 用户态音频操作的三个可靠工具

- `wpctl` — 音量/静音/状态（本插件已用）
- `pw-link -L` — 持久化连线，设备来去自动重连
- `pw-dump` — 完整节点图，做诊断和自动化

**避免** `pw-cli s` 改参数——不持久，session manager 重启即丢。

### 6.4 硬编码路径的坑

Decky v3.2.6 之前后端子进程**不继承 PATH**。本插件已改为优先探测 `/usr/bin` 等绝对路径（`bt.which()`），这是对的。
